## 功能实现总结

本节实现了三个系统调用：`sys_linkat`、`sys_unlinkat`、`sys_fstat`。
 `linkat` 用于在不同目录项之间建立硬链接，使两个路径指向同一 inode；`unlinkat` 用于删除目录项链接，当 inode 的链接计数减为 0 时回收对应的数据块和 inode；`fstat` 用于获取文件状态信息，包括 inode 编号、文件类型和硬链接数量等。
 通过实现这些功能，文件系统支持了多路径共享同一文件内容，并能正确维护引用计数与回收逻辑，确保文件系统一致性。

## 问答作业

### ch6

> 在我们的easy-fs中，root inode起着什么作用？如果root inode中的内容损坏了，会发生什么？

root inode 是整个文件系统的根节点，是访问所有文件与目录的入口。系统启动时通过它定位文件系统结构，其下的目录项形成完整的文件层级。如果 root inode 损坏，文件系统将无法找到任何文件或目录，相当于“失去了根目录”，整个文件系统结构会变得不可访问，数据虽然仍在磁盘上，但无法通过正常路径解析与访问。

### ch7

> 举出使用 pipe 的一个实际应用的例子。

在 Linux 终端中，`pipe`（管道）常用于将一个程序的输出作为另一个程序的输入。例如，统计文件的行数时，可以使用：

```shell
cat file.txt | wc -l
```

此命令中，`cat` 将文件内容输出到标准输出，而管道将该输出直接传递给 `wc`，由 `wc` 计算并输出行数。

> 如果需要在多个进程间互相通信，则需要为每一对进程建立一个管道，非常繁琐，请设计一个更易用的多进程通信机制。

可以设计一个 **消息队列机制** 或 **共享内存 + 信号量** 的组合。

- **消息队列机制：**
   内核维护一个公共消息队列，每个进程通过唯一标识（如队列 ID）发送或接收消息。进程间通信不再需要两两建立管道，而是通过统一的队列进行异步消息传递。
   优点：通信灵活、支持广播、多对多通信、无需建立大量管道。
- **共享内存 + 信号量机制：**
   将一块物理内存区域映射到多个进程的虚拟地址空间，所有进程可直接读写共享数据；再配合信号量进行同步与互斥控制。
   优点：高效（无需内核中转），适合频繁通信场景。
